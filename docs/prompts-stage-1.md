## Notas

### Desviación 1: dependencia `jackson-datatype-jsr310` agregada a `build.gradle`

La sección 1.3 de `refactor.pdf` dice que `build.gradle` ya incluye `jackson-datatype-jsr310`, pero el proyecto original solo tenía `jackson-databind:2.22.2`. Sin ese módulo, Jackson no puede serializar `java.time.LocalDate`, así que desde el Change 2 (fechas como `LocalDate`) `GET /loans` y `GET /reservations` responden 500. Javalin 7 registra el módulo automáticamente solo cuando está en el classpath.

Para cumplir lo que el documento da por hecho, se agregó una sola línea, con la misma versión de `jackson-databind` para evitar conflictos entre módulos de Jackson:

```groovy
implementation 'com.fasterxml.jackson.datatype:jackson-datatype-jsr310:2.22.2'
```

No se cambió nada más en `build.gradle`.

### Decisión 2: alcance del ítem 1a (header de licencia y javadoc) en el Stage 1

El Change 1 dice "every Java file", pero la rúbrica 1a (sección 6.1) evalúa "every file that Stage 1 touches". En el Stage 1, el header y el javadoc se aplican solo a los archivos que toca el Stage 1, más `index.html` y `logback.xml`. Los controllers, `App.java` y los tests quedan para el Stage 2 (ítem 1b), porque ese stage igual los modifica.
